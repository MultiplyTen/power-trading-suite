# 复盘调参模块

本版配置顶层db_path指向统一的../database/master.db。通过根目录main.py运行，或在本目录运行python main.py。

实际负荷和价格从四张事实表读取，发布结果直接写入runs/predictions；复盘直接读库，不再解析模型输出Excel。天气和其他维表沿用库内版本化结构表。

算法参数和输出报表沿用原功能，运行方法见../README.md，数据库维护见../database/数据库维护说明.md。历史独立版接口资料移入历史算法说明.md，不作为本版的数据接入操作指南。

## 原始事前负荷误差诊断

普通复盘额外生成 `load_risk_YYYYMMDD.json` 和逐小时、日型、近期、模型版本及配对明细 CSV，日/周/月 HTML 中提供链接。该诊断使用独立的默认90日滚动窗口，不等同于当前周/月子集。

通过 `database.forecast_errors` 只读选择每个目标日一份完整原始 M2 发布：在配置的 D−1 12:30 截点前发布，排除 replay、显式回测和晚发版本，不能把多个 run 对同一小时重复计入。实际值的可用和入库时间均不能晚于诊断 as-of。JSON 保留所选预测、实际修订和排除原因；它不等于对历史模型训练输入可得性的独立认证。

误差统一为 **实际负荷−预测负荷**。正 bias 表示低估负荷；WMAPE 为绝对误差总和除以实际电量总和，实际电量分母为零时保留未评估。均值 bias 的修正候选与去均值残差分位数分别展示，不自动改变预测或系数；分位数是历史描述，未经未来覆盖校准。默认少于7个完整日时，状态为 `insufficient_sample`，不输出修正候选或分位数，不把样本不足当零风险。即使 k=1，预测负荷与实际用电仍有量差敞口；该诊断没有估计金额预算或自动执行交易。不同模型版本可能覆盖不同日期，分组差异不能直接解释为改模增益。

## 研究调参的共同门槛

选择段和独立验证段均要求 `improvement >= improve_threshold`（默认5%）且日块 bootstrap 95% CI 下界大于0。候选只在选择段排名，胜出候选验证失败后不在验证段改选第二名。`apply` 重新检查两段幅度和 CI；旧版本缺少完整证据的建议需要重新复盘，不能仅保留 `validated: true` 绕过。

风险候选还要提供完整日收益及**原配置下重新评分**的场景审计。候选自己的置信度、auto 限额或可行标记不能作为通过依据：worker 保存参数变更前的配置，绑定基准风险输出及其 SHA256，在原历史窗口、原 error_shrink、原 confidence 和基准每日限额下重算候选研究曲线；场景与配置哈希必须一致。选择段和验证段均要求经验 CVaR90 日损失、同限额实际超限比例、逐日原场景超限比例及场景 CVaR 不增加，原约束场景可行日比例不下降。`apply` 再从序列化逐日审计重算这些门槛，不仅信任 passed 标签。少于10个完整日或缺证据时不通过，增加平均收益不能掩盖放松约束后的风险。场景仍沿用候选回测器的等权历史代理和最终快照，只能作为研究证据，不是严格事前风控全面验收。

`training.calendar_features` 的 `basic` / `enhanced` 已加入负荷候选网格，可在同一窗口比较日历增强。所有配置变更仍需显式执行 `apply`，普通复盘只写报告。

## 可复跑的离线冒烟

```bash
python review/tests/smoke_load_risk.py --output /path/to/new/disposable-directory
```

从仓库根目录运行，输出目录必须尚不存在。它仅构造合成 SQLite，验证原始事前配对、JSON/CSV 和日/周/月 HTML/Excel 链接，不训练模型、不使用真实业务数据、不回写配置。诊断合成结果为336个唯一小时、14个完整日，signed bias +2 MWh、WMAPE 16.67%，不能作为真实预测成绩。
