## D02 历史可得时间与截止并未全链统一

状态：**已有部分时点检查，仍有静态可见缺口。**

- 实时天气批次按截点前接收时间、龄期和完整城市/小时筛选，这是已有控制。
- 披露特征读取只筛选 `forecast + complete`，再按 `ingested_at/source_id` 取最后版本，没有按每个历史预测起点过滤可得时间。
- M2 统一发布读取取目标日最新完整 24 点，没有显式 `published_at <= historical_cutoff` 条件。
- M2/M3 配置截点为 D−1 12:30，但复盘迟发分类仍固定 D−1 09:00；执行对账使用配置截点。二者不能称为已经统一。
- `available_at` 可能是导入时间，不能自动当源发布时间。单值晚到当前透明提示，多值修订冲突仍阻断建议；最终快照回放不等于逐历史版本重建。

证据：[天气选择](https://github.com/MultiplyTen/power-trading-suite/blob/b679b20236db134789f58a2312bee1644c3d2b7e/database/weather.py#L48-L63)、[披露选择](https://github.com/MultiplyTen/power-trading-suite/blob/b679b20236db134789f58a2312bee1644c3d2b7e/load_forecast/evaluation/disclosure.py#L27-L40)、[统一发布读取](https://github.com/MultiplyTen/power-trading-suite/blob/b679b20236db134789f58a2312bee1644c3d2b7e/database/trading.py#L103-L116)、[迟发分类](https://github.com/MultiplyTen/power-trading-suite/blob/b679b20236db134789f58a2312bee1644c3d2b7e/review/reconciliation.py#L105)、[执行截止](https://github.com/MultiplyTen/power-trading-suite/blob/b679b20236db134789f58a2312bee1644c3d2b7e/review/execution.py#L19-L23)。

## D03 CI 日差的改善方向反向

状态：**代码与注释/判定不一致，未修复。**

`daily_metric` 对负荷、价格返回损失，对风险返回收益。注释要求正数表示改善：

```text
负荷/价格：基准损失 - 候选损失
风险：候选收益 - 基准收益
```

但当前实现为：

```python
direction = 1 if task == 'risk' else -1
d_sel = direction * (daily_metric(baseline) - daily_metric(candidate))
```

这使负荷/价格得到“候选损失−基准损失”，风险得到“基准收益−候选收益”，均与设计方向相反。后续仍用 CI 下界大于 0 作为通过条件，可能影响候选筛选及验证；不能把已有 CI 结果解释为已正确筛除噪声。

例：基准损失 10、候选损失 8，应得到改善 +2；当前日差为 −2。

证据：[指标定义与判定](https://github.com/MultiplyTen/power-trading-suite/blob/b679b20236db134789f58a2312bee1644c3d2b7e/review/suggestions.py#L156-L215)。

建议验收：分别用明确改善、无变化、明确退化的负荷/价格/收益序列验证日差和 CI 符号；覆盖选型与验证两段及实际候选选择路径。

## D04 建议生成与 apply 的门槛不一致

状态：**两端规则尚未对齐，未修复。**

建议生成写明 `improve_threshold` 仅用于展示，实际选择与通过以改善及 CI 判定。但 `apply_config.py` 仍要求 `item['improvement'] >= c['improve_threshold']`；配置仍为 0.05。

因此，按 CI 规则生成的不足 5% 改善建议，仍可能在人工 apply 时被拒绝。不能写成“5% 已被 CI 完整替代”。

证据：[生成规则](https://github.com/MultiplyTen/power-trading-suite/blob/b679b20236db134789f58a2312bee1644c3d2b7e/review/suggestions.py#L206-L215)、[apply 规则](https://github.com/MultiplyTen/power-trading-suite/blob/b679b20236db134789f58a2312bee1644c3d2b7e/review/apply_config.py#L53-L60)、[配置](https://github.com/MultiplyTen/power-trading-suite/blob/b679b20236db134789f58a2312bee1644c3d2b7e/review/config.yaml#L24)。

建议验收：先明确业务采用 CI、幅度门槛还是两者同时要求，再统一生成、展示和 apply。验证显著但小于 5%、大于 5% 但不显著及证据过期等情况。

## D05 负荷固定规格与选型状态标签不一致

状态：**计算分支可确认，结果标签需核对。**

默认 `selection_mode: fixed`，`load_object` 会关闭自动选型，使用配置对应的候选。但有有效验证记录时返回的 `selection_status` 仍可能是 `validation_selected`。该标签不能单独证明主模型由验证择优产生。

价格候选仍按选择窗指标择优，不能因负荷 fixed 就把所有模块都描述成固定模型。当前 `weather` 价格组还同时包含统调预测，因此该组增益也不等于天气单因素增益。

证据：[固定分支与返回状态](https://github.com/MultiplyTen/power-trading-suite/blob/b679b20236db134789f58a2312bee1644c3d2b7e/load_forecast/evaluation/rolling_backtest.py#L70-L95)、[价格特征组](https://github.com/MultiplyTen/power-trading-suite/blob/b679b20236db134789f58a2312bee1644c3d2b7e/load_forecast/evaluation/rolling_backtest.py#L137-L159)。

建议验收：fixed 与 validation 两种模式分别验证模型选择和元信息；需要解释天气独立增益时，单独增加统调特征消融。

## D06 求解模型与独立评分的等价性待数值核验

状态：**静态疑点，未运行复现；不作已确认数值故障结论。**

- 机会约束 Big-M 使用两条统一端点曲线的场景损失构造，需要确认它覆盖逐小时混合端点及全部可行系数的损失上界。
- LP 将 CVaR 阈值变量限制非负，而独立评分为 `max(CVaR(loss), 0)`；两者在包含盈亏混合的分布下是否等价需要独立核对。
- LP 返回结果存在时的状态标记应与求解器终止状态核对，不能只凭有解向量就宣称数学全局最优。
- 邻域检查只检查系数范围和平滑，不检查机会预算。邻域目标改善不能单独证明主解求解错误，也不能单独证明新方向满足所有风险约束。

证据：[目标评分](https://github.com/MultiplyTen/power-trading-suite/blob/b679b20236db134789f58a2312bee1644c3d2b7e/coefficient_opt/coefficient_optimization.py#L59-L73)、[求解实现](https://github.com/MultiplyTen/power-trading-suite/blob/b679b20236db134789f58a2312bee1644c3d2b7e/coefficient_opt/coefficient_optimization.py#L102-L204)、[邻域](https://github.com/MultiplyTen/power-trading-suite/blob/b679b20236db134789f58a2312bee1644c3d2b7e/coefficient_opt/coefficient_optimization.py#L245-L258)。

建议验收：用可枚举的小维场景与独立评分对照 LP/MILP，覆盖混合端点、正负损失、机会预算边界及超时结果。基准 k=1 超限本身不能证明所有候选不可行。
