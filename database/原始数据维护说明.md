# 原始数据版维护说明（优先于旧版说明）

## 数据流和权威来源

原始xlsx/zip → raw_sources.Cleaner（解析、统一日期小时、校验、保留来源格）→ commit_raw（每文件事务）→ master.db → 预测/优化/复盘。

零售加总是组合负荷主源；组织实际用电量只交叉核对。广东现货价格是价格预测主源；组织统一结算价只用于口径对照。实际成交量是执行记录，不把模型建议当作已经执行。相同文件可重导，不累加。

| 表 | 主键 | value单位/用途 |
|---|---|---|
| 负荷 | date,hour | MWh，组合负荷 |
| 用户明细 | date,hour,entity | MWh，entity为客户编码；name为名称 |
| 统调负荷 | date,hour | MW；hour为1—96季度时段序号 |
| 日前价/实时价 | date,hour | 元/MWh，业务主价 |
| 结算价对照 | date,hour,entity | 元/MWh，entity为da或rt |
| 申报记录 | date,hour | MWh，已成交量，允许已知次日计划 |
| 运行用电量对照 | date,hour | MWh，仅对照 |
| 负荷预测 | date,hour | 最新手填/模型值，MWh |
| 手填负荷预测 | date,hour | 独立保留手填值供模型失败兜底 |

扩展事实表共同含updated_at/source/available_at/evidence/source_sha/source_cell。available_at取真实本地接收时间，不能回填为假定平台发布时间。原有归档数据时间证据继续保留；旧快照没有满足完整发布时间证明，不能宣称严格实盘验证。

## 修订与恢复

`接入批次`存每个文件的SHA256、原始字节和摘要；`原始接入修订`保存完整主键、旧行、新行和接收时间。模型发布使用runs/predictions历史，不因当前预测表覆盖而丢失。当前模型预测写入负荷预测表，并在写之前保存手填快照。接入事务失败全部回滚，其他源文件不受影响。

`database/backups/`为提交前SQLite备份。恢复时停止程序，保留故障库，将已核验备份复制到新路径检查 `PRAGMA integrity_check`，再替换/修改四模块共同db_path。不允许初始化去覆盖损坏库。

## 下游适配与复盘

- `database.trading.dataset_frame`合并旧版本化客户/省级历史与新事实；新记录按业务键优先。新省级原始点只在每小时4点齐全时聚合均值。原始96点不修改。
- `coefficient_opt/config.yaml` 的use_system_load_feature默认false。启用时取system_load_lag_days（至少2）前同小时均值，且原数据须在该预测日D−1 09:00之前收到；缺失附哑变量，不读目标日实际负荷。启用后需独立回测，不声称已有收益改善。
- `review/config.yaml`的actual_lag_days_by_metric分别配置load/da/rt/settlement/declaration。当前4/5/5/5/0为本次2026-09-16相对末日的观察阈值，**不是固定平台承诺**；真实available_at仍是额外门槛，数据未齐继续等待。actual_lag_days保留为未配置指标的兼容值。调参候选沿用保守共同窗口及既有证据门槛。
- `review/execution.py`输出申报执行偏差CSV、结算口径对照CSV；仅与D−1 09:00前发布的同目标小时建议比较。无事前记录时标缺少，不伪造0偏差。研究建议与正式建议保留status。
- 2026-09-17次日成交量可入库，但截止9月16日执行复盘只分析384个已到日期的申报点；本次没有对应的事前发布建议，因此可比执行偏差样本为0，不能报策略实际收益。

## 格式变更时如何维护

先保留失败源文件和错误CSV，修改raw_sources.py的表头/标签解析；在test_raw_sources.py补对应格式案例，使用临时库验证整文件回滚和重复导入，再更新生产库。增加企业时更新原有客户地区映射契约；不要用企业名称自动猜用电地点。

四份源文件未提供单位/发布时间认证。当前按既有MWh约定入库且组织/客户数值吻合；若确认源单位为kWh，修改两个源单位配置并从原文件重导，历史错误记录通过修订保留，不直接改SQL抹去证据。

价格范围−1000～5000是样本质量检查阈值。217条负价保留；0按本业务要求视缺失。旧事实库68条零价保留为迁移档案，模型视图、复盘和导出均排除，不伪造历史删改。四类事实导出宽表缺少来源列，详尽来源通过数据库接入批次/修订定位；其他长表直接有来源。
