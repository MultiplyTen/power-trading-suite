# 四模块版数据库维护说明

主库：`database/master.db`。四个模块config.yaml的顶层db_path均指向它；实际路径相对各模块目录。运行日志、Excel模板和报告是普通文件，数据库是业务事实及发布记录的保存位置。

## 维护分工

| 数据 | 更新方式 | 当前权威存储 |
|---|---|---|
| 客户组合实际电量、日前价格、实时价格、手填预测 | data_ingest/data/输入模板.xlsx，然后运行data_ingest/main.py | 四张中文事实表 |
| 客户明细、全省负荷、天气、客户地区映射、城市坐标、日历 | 原database/manage.py版本化导入 | input_versions及对应current_视图 |
| 模型预测与系数决策 | 模型运行时自动从内存写入 | runs/predictions；中文查询视图 |
| 实际值修订与接收时间 | 数据接入事务自动记录 | 接入批次/接入修订/actuals |
| 参数调整 | 显式python main.py apply / rollback | config、adjustments和审计文件 |

本次升级保留原21份输入/来源文件的原始字节和410,390行结构化档案。旧组合负荷、价格、复盘Excel的current_表仅作为**迁移档案**保留，不再是四类小时事实的运行入口；不能用旧文件更新或activate回退这些事实，维护工具会明确拒绝。其余天气、客户明细等仍使用原版本化契约。

## 四张事实表

`负荷`、`日前价`、`实时价`、`负荷预测`字段一致：

- date、hour：北京时间日期及小时起点，联合主键。小时0—23。
- value：负荷统一MWh；价格元/MWh。
- updated_at：该数值最后真正变化的时间；同值重导保持不变。
- source：迁移历史、模板导入及小时/四段汇总方式。
- available_at：数据可用时间。新模板导入取真实接收时间，不把今天收到的修订回填成过去可见。
- evidence：初始档案继承原有假设/可用时间依据；新导入标为模板接收而非原平台发布时间证明。
- source_sha、source_cell：原始模板/批次及sheet行列定位。

空白不删除，非空upsert，错误整批拒绝。日期必须合法且同sheet不重复；负荷>0；数值有限；价格按配置范围；实际日期不晚于今天。历史迁入的空值及原有记录保持原貌，不使用新录入规则偷偷清洗历史。

24点直接存储；96点每四格合成一小时。负荷字段是时段电量，MWh求和、kWh先汇总再/1000；价格四点均值标为arithmetic_mean_proxy。不是瞬时功率，不自动把MW当电量。每小时不允许只填一部分15分钟值。

`接入批次`保存时间、模板SHA256、完整原文件BLOB及每sheet摘要；`接入修订`保存每个真正变化单元格的旧值、新值和位置。两张表与四张事实表、复盘实际值在同一事务提交。原始文件只读取一次，校验和存档使用同一份字节，避免保存中的Excel与已校验数据不一致。

`负荷预测记录`和`系数决策记录`是runs/predictions规范化物理表的中文查询视图，含发布时刻、模型版本和当次config快照。系数视图另提供declaration_quantity及research_declaration_quantity。不会用当前参数覆盖旧发布。这里的负荷记录沿用原复盘客户组合口径；客户明细与全省预测仍在负荷模块报表中。

复盘直接读取这些物理记录及事实表，不调用旧的capture、Excel预测解析或Excel实际值回填。历史研究回放由模型直接入库，保留晚发布标签及中性k=1说明。

## 日常操作

```bash
# 整个流程（先接入）
python main.py
# 只接入
python main.py input
# 数值查数导出（全库或日期范围）
python main.py export --from 2026-08-01 --to 2026-08-31
# 完整SQLite备份
python database/manage.py backup
# SQLite/归档检查
python database/manage.py check
```

导出Excel是四类当前数值的宽表，不包含天气、模型记录、参数、接收时间和旧版本。换电脑应复制整个项目及master.db，不要仅用四sheet文件代替全量迁移。

新接收的历史实际值会保留今天的可用时间，复盘可能提示数据修订或延迟到达，暂停历史调参。这不是入库失败；不能将available_at改早来通过回测。D+5复盘资格仍保留，模型观测滞后至少6天。

## 天气、明细及日历更新

在外部暂存目录准备完整快照，保持既有字段与单位。更新清单示例：

```json
{"files":[{"dataset":"load_forecast/data/weather_history.csv.gz","file":"weather_history.csv.gz"},{"dataset":"coefficient_opt/data/weather_history.csv.gz","file":"guangzhou_weather.csv.gz"}]}
```

```bash
python database/manage.py import --manifest /暂存目录/update.json --note "补充天气预报，维护人及来源说明"
python database/manage.py versions --dataset load_forecast/data/weather_history.csv.gz
```

逐文件版本表的current_视图、源SHA、行号、字段字典仍在catalog.json和input_quality中；直接改SQL映射表不会改变原始档案，因此不要SQL UPDATE这些表。天气固定提前量、发布时间、获取时间、实际天气的语义必须区分。天气单位：℃、%、mm、W/m²、m/s。日历当前2004—2026，下一年度按公布的调休安排更新完整calendar.csv，三模块共享，不必分别改代码。

共享输入版本、小时事实和读取代码均参与候选缓存指纹。实际值、日历等改变会使旧调参缓存失效。

## 备份、纠错及异常

写入前自动用SQLite backup API备份到database/backups；不自动删除旧备份。日常错误数值可在模板填正确值后重新导入，旧值留在接入修订中。不要删除历史审计。模型rollback仅回退模型参数，不回退业务数据。

库损坏/丢失时停止全部运行，保留故障文件，再恢复经过校验的备份。已有文件无论正常或损坏，init都拒绝覆盖；只有缺失且明确执行`python main.py init --confirm-empty`才建空库。空库没有天气、明细和日历，不能直接完成原三模块预测。

根目录与单模块运行共用database/.suite.lock；发现残留锁先核对PID及子进程均已结束，再清理，不要在正常运行时删除锁。备份和交接最好在停机后进行；同时保留config、exchange、output和正在填写的模板。

## 查询示例

```sql
SELECT date,hour,value,available_at,source FROM 负荷 ORDER BY date,hour;
SELECT date,hour,value FROM 日前价 WHERE date='2026-08-31' ORDER BY hour;
SELECT * FROM 接入修订 ORDER BY id DESC LIMIT 50;
SELECT run_id,target,load,published_at,config_json FROM 负荷预测记录;
SELECT run_id,target,k,declaration_quantity,published_at FROM 系数决策记录;
```

业务字段、全部源码、单元测试和验收证据均随包保留。统一库初始数据仍为历史研究材料；数据库接入成功不等于当前预测数据齐全，也不等于正式结算口径已经认证。
